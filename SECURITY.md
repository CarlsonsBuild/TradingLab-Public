# Public content safety policy

1. Private repositories stay private. Do not copy source code, diffs, stack traces, internal file paths, deployment configuration, secrets, broker identifiers or account details into public materials.
2. Public diagrams depict responsibilities, not implementation internals, trust boundaries or security-sensitive topology.
3. Every displayed metric must indicate whether it is synthetic, historical, paper-only, or an actual verified test result. Include date and source attribution for real metrics.
4. Do not expose a production endpoint or connect the public dashboard to any private system.
5. Do not disclose vulnerabilities in public issues. Contact the repository owner privately through an agreed secure channel.
6. Re-review each image and audio/video frame before distribution. Preserve an approved evidence manifest and rollback copy.
7. No representations of profitability or readiness without independently verified evidence.
